♿ How this mockup meets WCAG 2.1/2.2 AA

Circular.ie is a public body service, so this prototype is built against WCAG 2.1 Level AA (the standard required under Ireland's Public Sector Bodies accessibility regulations, transposing EU Directive 2016/2102) with a few 2.2 additions included. Specific decisions:

  • No swipe-only interaction (SC 2.5.1). Every card can be reached by touch swipe, the on-screen Previous/Next buttons, or the Left/Right arrow keys — swipe is an enhancement, never the only path.
  • A non-sequential alternative. "View as a plain list" shows every card in one scrollable, headings-based list — for anyone who finds one-at-a-time swiping slow, disorienting, or hard to target (motor, cognitive, or screen-reader efficiency reasons).
  • Screen reader announcements (SC 4.1.3). Card changes are pushed to a polite live region, so a screen reader user hears what changed without needing to re-explore the page.
  • No autoplay, nothing moves on its own. The tour only advances on explicit user action, avoiding the timing and motion pitfalls common to carousels (SC 2.2.2).
  • Keyboard operability (SC 2.1.1) and visible focus (SC 2.4.7). Every control is a real <button>/<input>, reachable in a sensible order, with a clear focus outline — including in Windows High Contrast / forced-colors mode.
  • Target size (SC 2.5.8). All interactive controls are at least 44×44px.
  • Colour contrast (SC 1.4.3 / 1.4.11). Text and button colours were checked against the WCAG contrast formula, not eyeballed — button text sits at 6.6:1+ in both light and dark themes, body text well above 7:1.
  • Colour is never the only signal (SC 1.4.1). The heart control changes shape, label and aria-pressed state, not just colour.
  • Reduced motion (SC 2.3.3). Anyone with prefers-reduced-motion set gets instant transitions instead of animated ones.
  • Forms (SC 1.3.1, 3.3.1, 3.3.2). The email field has a real <label>, helper text linked via aria-describedby, and an inline, programmatically-associated error if left invalid — not just a red border.
  • Zoom and reflow (SC 1.4.4 / 1.4.10). Sizing is in rem, not fixed pixels, and the layout is single-column, so it holds up at 200% zoom without horizontal scrolling.
  • No forced account creation. The email-to-self flow needs no password or login, which also keeps the form itself short and low-friction.

This is a design-stage mockup, not a compliance audit — a full VPAT / manual assistive-tech pass (NVDA, VoiceOver, JAWS, Dragon) against the final build is still the right next step before launch.
